Stage 1 · Onboarding

Registro + Cuenta CLABE + 1.er Cobro

  • • Info breve del proceso sin comisiones

  • • Link Payments (PAYMENT_LINK): compartir por WhatsApp, Correo, Screenshot o mensaje (POST /payment-link/create)
  • • QR Payments UI (CODI_QR): código QR CoDi en pantalla para cobro presencial (POST /codi/qr)
Stage 3 · Dashboard & Clientes

Tabla de Estatus, Recordatorios y Saldos

  • • Balance general (Cobrado vs. Pendiente por cobrar)
  • • Tabla con badges de estatus (Pagado, Pendiente, Vencido) y filtros
  • • Botón MSJ Reminder (WhatsApp/Correo) y Per Client Balance
  • • Agents Assistant: asistente por voz/texto

2. Secuencia de Cobro, Recordatorio y Conciliación Automática

Interacción con POST /payment-link/create y POST /codi/qr.

Sequence Diagram 
sequenceDiagram
    autonumber
    actor P as Practitioner (Profesor / Instructor)
    participant App as App (Dashboard / Assistant)
    participant API as Backend Go (/api)
    participant Pey as api.pey.mx
    actor C as Cliente / Alumno

    P->>App: Selecciona alumno ("Mateo · Mensualidad Basquetbol $850")
    P->>App: Elige canal (Payment Link o Código QR CoDi)
    App->>API: POST /api/payments
    API->>Pey: POST /payment-link/create o POST /codi/qr
    Pey-->>API: Devuelve paymentLinkUrl o qrString
    API-->>App: Registra PENDING_PAYMENT (Badge "Pendiente")
    App->>C: Envía link por WhatsApp/Correo o muestra QR en pantalla

    opt Si el pago sigue Pendiente
        P->>App: Filtra por "Pendientes" y toca "MSJ Reminder"
        App->>API: POST /api/payments/{id}/remind
        App->>C: Abre WhatsApp o Correo con recordatorio y link de pago
    end

    C->>Pey: Autoriza el pago desde su banco
    Pey->>API: Webhook firmado (standardwebhooks: payment_received)
    API->>API: Cambia estatus a SETTLED y actualiza Per Client Balance
    API-->>App: Badge cambia a "Pagado" y sube el Balance Cobrado
